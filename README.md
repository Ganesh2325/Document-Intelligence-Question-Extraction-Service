# Folio

Folio is a document intelligence workspace that turns messy examination papers into structured, reviewable question data.

It is not a PDF uploader with a chat box. It is an ingestion platform, an asynchronous processing engine, a question extractor, an answer-key matcher, and a source-traceability system.

The product loop is:

**Upload → Process → Understand → Validate → Review → Export**

## Features

- PDF, JPG, and PNG ingestion with magic-byte validation
- Native digital-PDF text extraction and Tesseract OCR fallback for scans/images
- Question boundary detection across numbering styles (`1.`, `Question 1.`, `Q1.`, `1)`, `(1)`, `Question No. 1`)
- Option extraction and question-type classification (MCQ, multi-select, true/false, fill-in, short, long, unknown)
- Multi-page question reconstruction (a question that starts on page 4 and continues on page 5 is one record)
- Answer-key detection in the same file, at the start/end, or in a related document
- Answers are matched by question number only. Conflicts stay `UNCERTAIN` with `value: null`
- Documented confidence scoring and a human review queue
- Source page (and region, when available) preserved on every question
- JWT auth, ownership checks, MinIO object storage, BullMQ workers
- FastAPI + Swagger UI, Postman collection, Docker Compose, automated tests

## Architecture

```
Next.js  →  FastAPI  →  PostgreSQL
                 │
               Redis / BullMQ
                 │
           Node.js worker
                 │
     MinIO  ·  PDF.js  ·  Tesseract  ·  heuristic extractor
```

See [docs/architecture.md](docs/architecture.md) and [docs/decisions.md](docs/decisions.md).

## Technology stack

| Layer | Choice |
| --- | --- |
| Web | Next.js, TypeScript, React, Tailwind CSS |
| API | **FastAPI** (Python) |
| Worker | Node.js, BullMQ |
| Database | PostgreSQL + Prisma migrations |
| Storage | MinIO (S3-compatible) |
| Queue | Redis |
| OCR | tesseract.js (local) |
| Extraction | Heuristic engine (default). Optional OpenAI if `AI_PROVIDER=openai` |

## Requirements

- Node.js 20+
- Python 3.12+ (FastAPI)
- Docker Desktop (for Postgres, Redis, MinIO — or the full stack)
- 4 GB RAM recommended if OCR is used on scans

## Quick start with Docker

```bash
cp .env.example .env
docker compose up --build
```

Then:

1. Open http://localhost:3000
2. Sign in with `recruiter@folio.dev` / `RecruiterDemo123!`
3. Upload files from `samples/`
4. Inspect Swagger at http://localhost:3001/docs

The API runs migrations on boot. Seed the demo user after the API is healthy:

```bash
docker compose exec api npx tsx prisma/seed.ts
```

Or from the host, with `DATABASE_URL` pointed at localhost:

```bash
npx prisma migrate deploy
npm run db:seed
```

## Local development (apps separately)

Start infrastructure:

```bash
docker compose up postgres redis minio
```

MinIO is pulled from `quay.io/minio/minio`. Redis is published on host port **6380** so it does not collide with other local Redis instances. Compose services still use `redis:6379` on the Docker network.

Copy environment and install:

```bash
cp .env.example .env
npm install
python -m pip install -r apps/fastapi/requirements.txt
npx prisma migrate dev --name init
npm run db:seed
npm run samples
npm run dev
```

Services:

| App | URL |
| --- | --- |
| Web | http://localhost:3000 |
| API | http://localhost:3001 |
| Swagger | http://localhost:3001/docs |
| MinIO console | http://localhost:9001 |

## Environment variables

See [.env.example](.env.example). Never commit `.env`.

Important provider flags:

| Variable | Default | Meaning |
| --- | --- | --- |
| `DOCUMENT_TEXT_PROVIDER` | `native` | PDF.js selectable-text extraction |
| `OCR_PROVIDER` | `tesseract` | Local OCR |
| `AI_PROVIDER` | `heuristic` | Rule-based extraction. **Not an LLM.** |
| `AI_PROVIDER=openai` | off | Uses `AI_API_KEY` if you explicitly opt in |
| `AI_PROVIDER=mock` | tests only | Deterministic fixtures — do not use silently in production |

## Processing pipeline

Documented in [docs/pipeline.md](docs/pipeline.md). Long work never runs inside the HTTP request. `POST /api/v1/documents/:id/process` enqueues a BullMQ job and returns immediately.

## Security

See [docs/security.md](docs/security.md). Highlights:

- bcryptjs password hashing and JWT access tokens
- every document/question route checks `ownerId`
- uploads validated by extension, size, and magic bytes
- objects stored under generated keys, never the original filename
- secrets stay on the server

## Scalability

Workers scale horizontally. `WORKER_CONCURRENCY` controls in-process parallelism. Storage is S3-compatible so MinIO can be replaced with AWS S3 without rewriting the domain model. The API is stateless.

## Trade-offs

- Default extraction is heuristic, not an LLM. That keeps the demo honest without API keys and avoids invented answers.
- Page images are generated sequentially so large PDFs do not explode memory.
- Preview rendering uses PDF.js + canvas; if a page cannot be rasterized, page-level provenance is still stored.
- JWT is stored in the browser for a simple SPA split. HttpOnly cookies would be the next hardening step.

## Known limitations

- Handwritten answers are not transcribed as student scripts; this product extracts printed questions.
- Nested multi-column layouts can reduce option-boundary confidence and will be sent to review.
- Related answer keys must be processed (or contain extractable text) before matching.
- `AI_PROVIDER=openai` still refuses to invent answers; it only assists question segmentation and falls back to heuristic on failure.

## Recruiter demo script

1. Sign in with the seeded account
2. Open Dashboard (live counts, not placeholders)
3. Upload `samples/01-clean-digital.pdf`
4. Watch Processing / Document timeline
5. Open a high-confidence MCQ and its source page

7. Group `05-question-paper.pdf` with `05-answer-key.pdf`
8. Upload `08-ambiguous-answer-key.pdf` and show the answer remaining UNCERTAIN
9. Reject `07-unsupported.txt`
10. Walk Swagger, Postman, Docker, and `npm test`
